# ADR-005 — Source-verified piece-level means and frozen groups

**Date:** 2026-09-25  
**Status:** provisional implementation choice; B05 acceptance blocked by unrun gates

Use the four verified OpenTextile v1.0 small tables, keyed by `Label`, with the 288-band mean SWIR reflectance vector as the only model input. Parse with stdlib CSV/JSON, verify bytes against both ignored B03 manifest and tracked source pin, carry 71 physical pieces and their original missing/flag status, and load B04's exact parent-group fold map. Pin the split file hash as well as the protocol file hash. Persist canonical JSON/JSONL locally with source, protocol and implementation hashes, placing spectra and label/context metadata in separate files joined by piece ID. Preserve an identity spectrum option and isolate the fixed per-piece source-informed PLS transform from any fitted cross-piece standardization.

Independent alternative search is recorded in `research/challenges/05_pipeline.md`. Cube or pixel expansion might study spatial heterogeneity but would add many correlated observations and unverified acquisition complexity without answering B04's piece-level supplier-label question. RGB fusion has a different ROI and no demonstrated fibre-specific gain, so it is context only. A binary array cache is unnecessary at 71 × 288 and would create an extra hash/schema boundary. Recomputing folds with a generic group splitter would violate the frozen B04 assignment. These choices follow the source article, B03 audit and official Python/SciPy/scikit-learn behavior, not an assumption of measured model performance.

Consequence: this path is small and auditable, but the source nominal labels, missing true chemistry, hidden supplier grouping and absent final set still limit any future result. Current testing prohibition prevents B05's clean reconstruction, leakage-violation and real smoke/memory gates; B05 remains `needs_revision` with no claim that implementation works in execution.

**2026-09-26 recovery amendment:** static inspection of the unexecuted first draft found an absolute checkout path in derived split bytes and a combined features/target JSONL record. The implementation now emits separate spectral and metadata JSONL records and pins the B04 split SHA-256 `f39f304523ffecb130541de7194a2bdfb3e3f0564313ab0c137b427aad1196c7`. No prior derived outputs existed or were replaced. The independent B05 challenger had already identified feature/target separation as a leakage guard. No runtime result or gate status changed.

**2026-09-26 continuation:** a second independent read-only reviewer identified the `exists()`/`os.replace()` overwrite race, the caller-supplied group-ID boundary and basename-only provenance keys. Based on official Python filesystem semantics and the local one-writer design, publication now uses a same-directory temporary file plus no-overwrite hard link, with repository-relative code-hash keys. The group-ID boundary remains explicit until frozen-split integration is executed. This is an untested implementation amendment, not a gate pass.
