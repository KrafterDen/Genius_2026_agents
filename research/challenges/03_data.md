# B03 independent data challenge

The primary source was not selected merely because it was named in the prompt. Two read-only native workers independently assessed source access and label provenance. The label challenger favored NIST Source A/B: its manufacturer specifications carry product and lot information, whereas the [NIST descriptor](https://www.nature.com/articles/s41597-026-07434-6) cautions against treating Source C/D care labels and product cards as validated chemistry. This is an argument for **auditing NIST first when its files can be read**, not a claim that NIST already passes the 80% cotton or 95% polyester target gate.

The same challenger noted that OpenTextile's 11 outlier flags were obtained by fitting a spectral model across its collection. The [authors' methods](https://pmc.ncbi.nlm.nih.gov/articles/PMC12925456/) confirm this. Removing those 11 globally would privilege a model-compatible subset and make a later holdout claim suspect. B03 therefore keeps flagged rows visible and separate. Three unknown-composition rows remain unknown. The parent-prefix rule groups the two `sample_45` pieces, while admitting that hidden supplier/batch dependence may remain.

The root independently located the [NIST RMM record](https://data.nist.gov/od/id/mds2-3325) and its small file hashes, and found an [official data.gov pointer](https://catalog.data.gov/dataset/near-infrared-spectra-of-origin-defined-and-real-world-textiles-nir-sort-a-spectroscopic-a) to a [Materials Data Facility mirror](https://acdc.alcf.anl.gov/mdf/detail/7e12131d-87fe-435b-8de4-757bd52f78a5-1.0/). Bounded direct NIST file requests stalled despite successful RMM metadata access. The mirror's available path led to a Globus file manager; small file access and any account requirement remain unresolved at this checkpoint. No NIST composition table was silently inferred from the paper's headline total of 113 fabrics.

Alternative [HyperTex](https://zenodo.org/records/21489250) has prospective chemical-label strengths but its files are embargoed until 2026-09-30. Existing chemically referenced textile studies in `research/prior_art_matrix.csv` do not provide verified downloadable specimen spectra here. Obtaining data by contacting authors or using paid services would be outside current authorization; the project proceeds on accessible OpenTextile for a narrower question.

The access challenger additionally found [FasTEX/KCL v3](https://data.mendeley.com/datasets/rx3fjgz96x/3), CC BY 4.0, with 160 ATR-FTIR spectra from 137 pure, non-blended samples. It is a useful lawful pure-fibre reference, but ATR-FTIR and absent mixture percentages make it a poor replacement for this NIR blend-composition question. The [Stipanovic et al. cotton/polyester study](https://doi.org/10.3390/recycling10040152) has stronger chemical reference labels, but no reusable raw NIR spectra file was located in its public dataset statement during this search. These are exclusion reasons, not assumptions that either source is inferior in all applications.

**Adversarial capacity calculation.** OpenTextile has 10 unflagged nominal positives for ≥95% polyester and 6 for ≥80% cotton. A disjoint train/selection/calibration/final evaluation cannot reserve many positive groups for each stage. Even if all 10 polyester positives were accepted in one independent evaluation with no observed false acceptances, a one-sided 95% binomial risk upper limit would be approximately 25.9%. Thus a 5% false-acceptance guarantee is unsupported before any model exists. For ≥80% cotton, two of six nominal positives sit exactly at the stated threshold, adding reporting ambiguity. The approximately 88% cotton Infinited preference is not an exact binary eligibility rule.

**Challenge verdict.** File access and labels suffice for a transparent grouped exploratory/reproduction study, not the proposed selective-risk confirmation. Choosing NIST without its sample table would be equally unsupported. Reopen the target decision if NIST A/B files or HyperTex release provide stronger independent and auditable labels. Preserve incompatible instruments as separate domains unless an explicit transfer protocol justifies combining them.
