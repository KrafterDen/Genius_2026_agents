## 2026-09-26 independent static review and write-once alternative

A read-only Sol Medium reviewer traced the amended B05 code and found three concrete limits. First, `Path.exists()` followed by `os.replace()` left a race in the promise never to overwrite an already created derived file. The [Python `os.replace` documentation](https://docs.python.org/3/library/os.html#os.replace) explicitly says an existing file destination is silently replaced. The implementation now writes to a same-directory named temporary file and attempts [a hard link](https://docs.python.org/3/library/os.html#os.link) at the destination, comparing hashes if the name already exists, then removes the temporary name. [Python's temporary-file documentation](https://docs.python.org/3/library/tempfile.html#tempfile.NamedTemporaryFile) describes `delete=False` and cleanup responsibilities. A lock file was the alternative, but it adds stale-lock recovery and is unnecessary for the local one-writer process; the link operation still needs real platform execution before its behavior can be claimed as validated.

Second, the feature standardizer checks only caller-supplied group strings; it cannot verify that future rows were assembled from the frozen piece-ID map. That integration boundary is documented, not called a passed leakage gate. Third, provenance hashes keyed only by basename could collide as code grows; they now use unique repository-relative paths. No reviewer or root tests, smoke command or model fit were run.
