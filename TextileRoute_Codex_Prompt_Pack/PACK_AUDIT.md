# Package audit — 25 September 2026

## What was actually produced
- Twenty numbered English work-block prompts00–19, plus AUTOPILOT, RESUME and independent CHALLENGER prompts.
- Repository/control templates, six project-scoped agent configuration examples, model-routing/research/scientific policies and a stage-specific submission inventory.
- Twenty-seven source records with limitations; a dated requirements snapshot; explicit unresolved data, rules and authorship questions.
- An optional opt-in local runner, structural/integrity validator and24 offline automated tests.

## Validation actually performed
The24 tests passed using controlled local fixtures and mocked Codex process boundaries. They covered dry-run behavior, false completion, missing evidence, path escape, permission-bypass rejection, version changes, locks, interruption/failure contracts, skipped completed blocks and invocation caps. JSON/TOML examples, numbered-prompt structure and final file hashes are checked by tools/validate_pack.py.

## What was not performed
No Codex session was launched on the user's computer. The user's installed CLI, account/model availability, native agents and network access were not tested. No textile model was trained. No dataset files/license were downloaded or audited. No experiment, report findings, industrial validation, student contribution or completed application is claimed. Bootstrap and later gates must do that work.

The runner is not a proof of scientific validity: it checks explicit status/evidence artifacts and stops on missing/failed gates. Independent reviews and real experiment checks are still required. Planning allocations are not guaranteed elapsed time.
